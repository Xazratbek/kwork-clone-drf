KWORK CLONE DRF MODELLAR VA RELATIONLAR
Versiya: 1.0
Sana: 2026-06-13

Notation:
- FK(A) = foreign key to A.
- O2O(A) = one-to-one to A.
- M2M(A) = many-to-many to A.
- Owner fields uchun CASCADE/PROTECT tanlash pastda ko'rsatilgan.
- Money fieldlar Decimal yoki integer cents/tiyin sifatida saqlansin. Tavsiya: amount_minor integer + currency char(3).

14. Delete behavior

- User real delete qilinmaydi; soft delete/status. Orders/payment/reviews saqlanadi.
- Kwork delete = archive. Order mavjud bo'lsa hard delete yo'q.
- Category delete faqat child/kwork yo'q bo'lsa; aks holda deactivate.
- Payment/refund/ledger hard delete taqiqlanadi.
- Message/attachment retention config bilan; MVP hard delete admin-only.

15. Snapshot fields kerakligi

Orderda title_snapshot, package_name_snapshot, price snapshots saqlansin. Chunki seller kworkni keyin tahrirlasa eski order shartlari o'zgarmasligi kerak.

16. Constraintlar

- Seller own kwork sotib ololmaydi.
- Kwork active bo'lishi uchun kamida 1 package, 1 primary image, category, title, overview, requirements bo'lishi kerak.
- Package price >= platform minimum.
- Custom offer price >= platform minimum.
- Proposal per seller/request unique.
- Review only completed/canceled orderdan keyin.
- Payment callback idempotent.
- Refund amount <= paid amount.
- Earning only completed order uchun.
