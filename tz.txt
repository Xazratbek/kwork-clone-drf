KWORK CLONE DRF TEXNIK TOPSHIRIQ
Versiya: 1.0
Sana: 2026-06-13
Platforma turi: freelance marketplace, fixed-price service catalog + buyer request exchange.

1. Maqsad

Kwork.com asosiy biznes modeliga yaqin DRF backend clone yaratish. Platforma ikki tomonli marketplace bo'ladi:
- Buyer xizmat sotib oladi yoki buyer request joylaydi.
- Seller kwork nomli tayyor xizmat paketlarini yaratadi, buyurtma qabul qiladi, ish topshiradi.
- Admin/moderator kwork, request, order, dispute, review, user content, payment simulationni boshqaradi.

To'liq 1:1 clone qilinmaydi. MVP asosiy oqimlarni qamraydi: katalog, qidiruv, filtr, kwork detail, package/extra option, order, escrow-like payment simulation, chat, delivery, revision, cancellation, review, seller profile, buyer request/exchange, custom offer, moderation.

2. Kwork haqida qisqa tahlil

Kwork - freelance service marketplace. Xizmatlar "kwork" sifatida katalogda sotiladi. Buyer katalogdan tayyor fixed-price xizmat sotib oladi yoki Exchange orqali maxsus request beradi. Seller kwork yaratadi, buyer oldindan to'laydi, platforma to'lovni ushlab turadi, seller ishni topshirgach buyer tasdiqlasa sellerga earnings yoziladi. Rasmiy Terms bo'yicha:
- Har user buyer ham seller ham bo'lishi mumkin.
- Kwork minimum fixed price $10.
- Package kwork bir nechta narx/service set beradi.
- Extra option asosiy xizmatga qo'shimcha pullik xizmat.
- Order page buyer va seller muloqot qiladigan joy.
- Buyer oldindan order uchun to'laydi.
- Deliverydan keyin buyer tasdiqlaydi yoki revision so'raydi; javob bo'lmasa avtomatik approve bo'ladi.
- Canceled order refund qiladi.
- Contact/payment off-platform taqiqlanadi.
- Kwork va buyer request manual approvaldan o'tadi.

4. MVP modullar

4.1 Auth va account
- Email/password signup.
- Email verification.
- Login/logout/JWT.
- Password reset.
- User username unique.
- User bir accountda buyer va seller bo'lishi mumkin.
- Account status: active, suspended, blocked, deleted_pending, deleted.
- Blocked user yangi order boshlay olmaydi, active orderlarni yakunlashi mumkin.

4.2 Profile
- Buyer public/private profile.
- Seller public profile.
- Avatar, country, language, timezone.
- Seller display name, headline, bio, skills, response time, online/offline, joined date.
- Seller rating, completed orders, reviews count, orders in progress.
- Seller level: new, advanced, professional.
- Buyer level: new, rising, experienced, seasoned, established, expert, top.

4.3 Category catalog
- 3-level tree: root category, subcategory, niche/category child.
- Root examples:
  - Design
  - Development & IT
  - Writing & Translations
  - SEO & Web Traffic
  - Digital Marketing & SMM
  - Audio & Video
  - Business & Lifestyle
- Category slug unique.
- Category-specific attributes/filters.

4.4 Kwork service
- Seller kwork yaratadi.
- Kwork fields:
  - title
  - slug
  - category
  - description/overview
  - requirements_from_buyer
  - status
  - moderation_status
  - base price
  - packages
  - delivery time
  - revisions
  - media gallery
  - tags
  - FAQ
  - attributes
  - extra options
- Status: draft, pending_review, active, rejected, paused, archived, blocked.
- New seller initial limit: 20 kworks. First completed orderdan keyin limit 300.
- Edited active kwork qayta approvalga tushadi.
- Duplicate/prohibited/off-platform/contact info validation kerak.

4.5 Packages
- Package kwork 1 yoki 3 package bilan ishlaydi.
- Package names: Basic, Standard, Premium.
- Har package:
  - summary
  - price
  - delivery_days
  - revision_count yoki unlimited flag
  - included feature/value rows
- Detail page "Select a Package" table ko'rinishida bo'ladi.

4.6 Extra options
- Seller extra option qo'shadi.
- Extra option name, description, price, extra_days, active.
- Extra option asosiy package ichidagi service bilan redundant bo'lmasligi kerak.
- Buyer order paytida tanlaydi.

4.7 Search, filter, sort
- Search input header va hero.
- Search by title, description, tags, seller username.
- Filter:
  - category/subcategory
  - price min/max
  - seller level
  - seller activity
  - positive reviews %
  - delivery time
  - orders in progress
  - service includes/category attributes
  - tags
- Sort:
  - relevance
  - newest
  - price low/high
  - rating
  - orders completed
  - delivery fastest
- Grid/list toggle.

4.8 Favorite
- Buyer/authorized user kworkni favorite qiladi.
- Favorite listing va detail page yurak icon.
- Guest bosganda login modal.

4.9 Order
- Buyer package + extras tanlaydi.
- System price hisoblaydi:
  subtotal = package_price + selected_extras_sum
  platform_fee = buyer_fee_config yoki 0
  total = subtotal + platform_fee
  seller_earning = subtotal - seller_commission
- Order statuses:
  draft
  payment_pending
  paid
  seller_pending_acceptance
  in_progress
  delivered
  revision_requested
  completed
  cancellation_requested
  canceled
  disputed
  overdue
- Payment successdan keyin order seller_pending_acceptance.
- Seller 24 soat ichida accept qilmasa buyer refund mumkin yoki auto cancel.
- Acceptdan keyin deadline = accepted_at + delivery_days + extra_days.
- Seller deadline o'tsa order overdue.
- Seller delivery yuboradi: message, files, proof.
- Buyer approve qilsa completed, earnings pending/available.
- Buyer revision so'rasa revision_requested, seller qayta delivery qiladi.
- Buyer javob bermasa auto approve:
  - total <= $150: 3 business days, weekend ko'p bo'lsa 4 days.
  - total > $150: 5 business days, weekend ko'p bo'lsa 6 days.
  MVP: cron/scheduled task bilan working-day approximation.

4.10 Requirements
- Order boshlanishi uchun buyer seller talab qilgan data yuboradi.
- Requirement fields:
  - text questions
  - file upload
  - links
- Requirement yuborilmaguncha seller deadline boshlanmasligi mumkin. MVPda paymentdan keyin requirements_required status qo'shish mumkin.

4.11 Chat/messages
- Order page ichida buyer-seller message.
- Direct seller contact tugmasi kwork detailda bor.
- Off-platform contact/payment keyword detection.
- Attachment upload.
- Message read status.
- System messages: order created, payment paid, seller accepted, delivery sent, revision requested, completed, canceled.

4.12 Delivery/revision
- Seller delivery record yaratadi.
- Har delivery version saqlanadi.
- Buyer action:
  - approve
  - request_revision(reason, attachments)
  - cancel/dispute
- Revision count limit packagega bog'liq. Unlimited bo'lishi mumkin.
- Agar seller delivery incomplete bo'lsa buyer cancellation/dispute ochadi.

4.13 Cancellation/refund
- Buyer 20 minut ichida orderni cancel qila oladi.
- Seller 24 soatda start/accept qilmasa buyer refund.
- Seller deadline o'tkazsa buyer refund.
- Buyer va seller mutual cancel.
- Moderator poor/incomplete delivery deb topsa refund.
- Refund status:
  requested
  awaiting_counterparty
  auto_approved
  approved_by_moderator
  rejected
  processed
- Simulated payment provider refund callback yaratadi.

4.14 Review/rating
- Completed yoki canceled orderdan keyin buyer review berishi mumkin.
- Review window: 30 days. Ba'zi category uchun 60 days config.
- Fields:
  - rating 1-5
  - text
  - is_positive
  - public/private moderation status
- Positive review 30 days ichida edit/delete.
- Negative review 2 days ichida edit.
- Review seller ratingga ta'sir qiladi.
- Seller reviewga javob yozishi mumkin.

4.15 Portfolio
- Seller portfolio work yaratadi.
- Portfolio kwork bilan bog'lanishi mumkin.
- Fields: title, description, images, category, project_url optional, buyer/order optional, visibility.
- Kwork detailda "Portfolio (N works)" slider/grid.

4.16 Buyer request / Exchange
- Buyer custom task request yaratadi:
  - title
  - description
  - category
  - budget
  - delivery_days
  - files
  - visibility/status
- Request ham manual approvaldan o'tadi.
- Seller requestga proposal/custom offer yuboradi.
- Buyer proposalni accept qilsa custom order/payment oqimi boshlanadi.
- Generic copy-paste proposalsni kamaytirish uchun:
  - per request seller faqat 1 proposal.
  - proposal text minimum length.
  - budget/delivery explicit.

4.17 Custom offer
- Seller buyerga custom offer yuboradi.
- Custom offer direct chatdan yoki buyer requestdan keladi.
- Fields: title, description, price, delivery_days, revision_count, included_items, expires_at.
- Buyer accept qilsa order yaratiladi va payment pending bo'ladi.

4.18 Payments
- Real production payment emas. Click va Payme test mode/simulation.
- Providers:
  - click_test
  - payme_test
  - manual_test/admin_mark_paid
- Payment model:
  - provider
  - provider_transaction_id
  - amount
  - currency
  - status
  - raw_request/raw_response
- Payment statuses:
  initiated
  pending
  succeeded
  failed
  canceled
  refunded
- Escrow simulation:
  - buyer payment succeeded -> order funds_held.
  - order completed -> seller earning available.
  - order canceled/refunded -> buyer refund transaction simulated.
- No internal wallet required in MVP. Balance page can show available/pending earnings only.

4.19 Payout simulation
- Seller earnings ledger.
- Earnings statuses:
  pending_clearance
  available
  payout_requested
  paid_out_test
  reversed
- Payout provider simulated.
- Admin can mark payout paid.

4.20 Moderation
- Moderation queue:
  - kwork
  - buyer request
  - portfolio
  - review
  - report
- Decision: approve, reject, request_changes, suspend.
- Rejection reason required.
- Audit log required.

4.21 Notifications
- In-app notification.
- Email stub/log.
- Events:
  - kwork approved/rejected
  - order paid/accepted/delivered/completed/canceled
  - revision requested
  - message received
  - custom offer received/accepted/expired
  - payout status changed

4.22 Reports/support
- User report content/user/order.
- Support ticket:
  - subject
  - category
  - related order/kwork/user
  - messages
  - status
- Dispute order bilan bog'lanadi.

6. Permissions

- Guest: read public active content only.
- Auth user: favorite, message only allowed contexts, buyer actions.
- Seller owner: own kworks CRUD; cannot approve own content.
- Buyer owner: own orders/requests actions.
- Order participant: order detail/messages.
- Moderator: moderation/dispute/report read/write.
- Admin: full.

7. Non-functional talablar

- DRF + PostgreSQL.
- Media files local dev, production uchun S3-compatible storage optional.
- Search MVP: PostgreSQL trigram/full-text. Later Elasticsearch/OpenSearch.
- Celery/cron:
  - auto approve delivery
  - order overdue check
  - custom offer expire
  - seller pending accept timeout
  - notification email send
- Audit logs for payment, moderation, order status changes.
- Idempotent payment callbacks.
- Money fields Decimal, integer cents/tiyin recommended.

- Tests:
